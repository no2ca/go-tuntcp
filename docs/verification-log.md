# 検証の記録

[CLAUDE.md](../CLAUDE.md) の「検証」の方針が、うまくいっているかを確かめるための記録。

確かめたい仮説は次のとおり。

- 人間が差分を全部読まなくても、「仕様 ↔ テストの意図 ↔ 証拠」の対応を確かめることで、正しさを保てる
- 仕様と文書から説明できないコードを、少なく保てる
- 機能と実装の対応を、粒度を変えて説明できる
- 上の 3 つによって、ほかの方法で個人開発を進めたときと同じ水準に、より速く、人間の認知の負荷を下げながら届く

完璧な検証は目指していない。比べる相手は「全部のコードを自分で読み書きする個人開発」である。

新しいものを上に足す。1 件は次の形で書く。

```
## 日付  タスク  種類
- やったこと:
- 結果:
- 方針への影響:
```

種類は、対応表の確認、抜き取り、予想の確認、あとで見つかった誤り、負荷の気づき、方針の変更のどれか。
「負荷の気づき」には、報告が長すぎた、確認が面倒だった、逆に楽だった、といった人間の感想を書く。

## 2026-11-13  T7-1〜T7-7  あとで見つかった誤り

- やったこと: M7 を AI が自走で実装した。テストを先にコミットし、実装を 2〜4 段に分けて、各段のあとで残りのテストが本題の理由で落ちていることを確かめた
- 結果:
  - 先に書いたテストの誤りが 1 つ: `TestHandle_CloseWait_ACK_SendsRemainingData` は、FIN のセグメントが既定のウィンドウ 65535 を広告していて、準備した「ウィンドウ 5」を上書きしていた。実装の前は準備の段階（CLOSE-WAIT に入れない）で落ちていたので、見えなかった。実装を段に分けたので、ACK の処理を入れる前に「期待しない落ち方」として見つかった
  - RFC の文面の順番どおりでは起きない処理が 1 つ: TIME-WAIT での「相手の FIN の再送で 2MSL を数え直す」。再送された FIN は First で受理できず、文面が書かれている Fifth と Eighth に届かない。テストを書くために入力を具体的に決めたところで気づいた
  - RFC の節どうしの食い違いが 1 つ: RST を送った側は TIME-WAIT に入る（3.5.2）と、CLOSED にする（3.10.5）
  - 最初から通ったテスト: `TestHandle_Established_FINNotAtRcvNxt_NotProcessed` の 4 行のうち 3 行（FIN を無視する実装でも通る）、CLOSE-WAIT と FIN 受信後の「FIN の再送に ACK」「データを無視」（First と Seventh の既存の条件で通る）、`TestHandle_TimeWait_PureACK_NoReply`、`TestTimeWait_OtherSegments_DoNotRestartTimer`（数え直しを入れる前から通る）。どれも、あとから入れる実装が壊してはいけない振る舞いの確認
  - 実機の確認の前提が、環境で 2 つ違った: `task` が入っていない、tcpdump が権限を落とせずに終わる（`-Z root` で直した）。`curl` の最中の `ss` の検査は、接続が 1 ミリ秒で消えるようになって成り立たなくなり、外した
  - 記録に残らない確認が 1 つ: `main` が 1 秒おきに `HandleTimeouts` を呼ぶ配線は、MSL を一時的に 0.5 秒に縮めて、TIME-WAIT の接続が消えることを 1 回だけ見た
- 方針への影響: 実装を段に分けて、段ごとに残りの落ち方を読むと、「落ちる理由が 2 つ以上あるテスト」の 2 つ目を実装の前に見られる。落ちる状態が履歴に残るのは最初の 1 回だけで、段ごとの確認は残らない。RFC の文面どおりに並べても届かない処理があるので、「段階の順番どおりに並べる」だけでは仕様を満たしたことにならない

## 2026-11-11  T6-1〜T6-7  あとで見つかった誤り

- やったこと: M6 を AI が自走で実装した（人間は大きな粒度での負荷を見る）
- 結果:
  - 先に書いたテストの誤りが 1 つ: `TestHandle_Established_WindowUpdate` の「SEG.SEQ == SND.WL1」の行は、データのない ACK を RCV.NXT より前の SEQ で送っていた。First で捨てられて Fifth まで来ないので、どんな実装でも通らない。実装の前は準備の段階（`Snd.WL1` の確認）で落ちていたので、この行の誤りは実装のあとで初めて見えた。RCV.NXT をまたぐデータを載せて直し、直したテストを実装の前のコードで実行して、落ちることを確かめ直した
